`@webfrost/sdk` is a typed TypeScript client for the [REST API](/docs/reference/rest-api). It wraps `fetch`, has no dependencies, and runs on Node 18+, Bun and in browsers. It is ESM only and ships its type declarations.

## Install

```sh
npm install @webfrost/sdk
```

It is not on npm yet: the package will be published with the first release, `0.1.0`.

## Create a client

```ts
import { WebFrostClient } from "@webfrost/sdk";

const client = new WebFrostClient({
  // The server's origin; the client talks to its /api/v1 itself.
  baseUrl: "http://localhost:3000",
  apiKey: process.env.WEBFROST_API_KEY,
});
```

| Option | Type | Default | Description |
|---|---|---|---|
| `baseUrl` | `string` | `""` | The server's origin, such as `http://localhost:3000`, optionally with the path a reverse proxy serves WebFrost under (`https://example.com/webfrost`). The client appends `/api/v1` and the route itself. The default, an empty string, is the page's own origin, for a browser page served by WebFrost. A trailing slash is removed. |
| `apiKey` | `string` | none | Sent as `Authorization: Bearer <key>` on every request. Create one in the UI, with `webfrost admin key create`, or through `completeSetup`. |
| `timeoutMs` | `number` | `30000` | Per-attempt timeout, covering the response headers and body. `0` disables it. |
| `retries` | `number` | `0` | How many times to retry a failed GET or HEAD. See [Timeouts, retries and abort](#timeouts-retries-and-abort). |
| `retryDelayMs` | `number` | `250` | Base delay for exponential backoff with jitter. |
| `maxRetryDelayMs` | `number` | `30000` | Longest wait between attempts. A longer `Retry-After` is not waited out. |
| `credentials` | `RequestCredentials` | `"same-origin"` | The `fetch` credentials mode. Use `"include"` for a browser page on another origin that relies on the session cookie. |
| `fetch` | `typeof fetch` | global `fetch` | A custom `fetch` for SSR, tests or proxies. The global is looked up on every request. |

The client speaks version 1 of the [REST API](/docs/reference/rest-api#versioning) (`/api/v1`). `baseUrl` is where the server is, not where its API is. A legacy value ending in `/api` or `/api/v1` still works: the client drops the suffix and logs a one-time `console.warn`.

Timestamps (`createdAt`, `lastRunAt`, `nextRunAt`, `expiresAt`, ...) are ISO 8601 strings in UTC, such as `"2026-11-21T21:42:38Z"`: pass them to `new Date()` as they are.

## Authentication

| Where | Use | Why |
|---|---|---|
| Node, Bun, scripts, servers | `apiKey` | Sent as `Authorization: Bearer <key>` on every request. |
| A browser page served by WebFrost | the session cookie | `login()` sets it and the browser sends it. Leave `apiKey` out. |
| A browser page on another origin | `credentials: "include"` | Needed for the cookie to be stored and sent cross-origin. |

Outside a browser nothing keeps a session cookie, so `login()` is not useful there: use an API key.

## Errors

Every failure is a `WebFrostError`, never a bare `TypeError` or `AbortError`:

```ts
import { WebFrostError } from "@webfrost/sdk";

try {
  await client.createSnapshot("not-a-url");
} catch (err) {
  if (err instanceof WebFrostError) {
    console.error(err.status, err.code, err.message); // 400 "VALIDATION" "invalid url"
    // err.retryAfter: seconds from the Retry-After header, when sent (typically on 429)
  }
}
```

| Field | Meaning |
|---|---|
| `status` | HTTP status, or `0` when there was no response |
| `code` | Machine-readable: the server's `code` (`VALIDATION`, `UNAUTHORIZED`, `INVALID_CREDENTIALS`, `FETCH_FAILED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `RATE_LIMITED`, ...; the full list is in the [REST API errors](/docs/reference/rest-api#errors)), or from the client `NETWORK_ERROR`, `TIMEOUT`, `ABORTED`, `INVALID_RESPONSE`. Branch on this, not on `message`. |
| `message` | The server's `error` text, or the status text |
| `retryAfter` | Seconds to wait, from `Retry-After` |
| `cause` | The underlying error for network failures and timeouts |

**Not found.** A single lookup that finds nothing resolves `null` (`getSnapshot`); a delete of something missing resolves `false` (`deleteSnapshot`, `deleteTag`, `deleteSchedule`, `revokeApiKey`, `removeTagFromSnapshot`); listing the tags of a missing snapshot resolves an empty page. Every other 404 throws with code `NOT_FOUND`.

## Timeouts, retries and abort

Every method takes a final `{ signal }` argument. It is combined with the client's timeout, and either one ends the request: `ABORTED` for the signal, `TIMEOUT` for the timeout.

```ts
const controller = new AbortController();
const page = client.listSnapshots({ status: "done" }, { signal: controller.signal });
controller.abort(); // rejects with WebFrostError, code "ABORTED"
```

With `retries` set, **GET and HEAD** requests are retried on network errors, timeouts, `429` and `502`/`503`/`504`, with exponential backoff and jitter. A `Retry-After` header is honoured; if it is longer than `maxRetryDelayMs` the error is thrown instead of waiting. Writes are never retried: a POST or PATCH that reached the server could run twice, and a retried DELETE would report "not found" for something it had just deleted.

## Pagination

Every list method (`listSnapshots`, `searchSnapshotsPage`, `listTags`, `listSnapshotTags`, `listSchedules`, `listApiKeys`, `listImports`) takes `(options?: { page, limit }, request?: { signal })` and returns a `Page<T>`: `{ items, total, page, limit }`. `limit` defaults to 20 and the server caps it at 200.

```ts
const { items, total, page, limit } = await client.listTags({ page: 1, limit: 50 });
```

The lazy iterators `iterateSnapshots`, `iterateTags`, `iterateSchedules`, `iterateApiKeys` and `iterateImports` fetch one page at a time (100 per request unless `limit` says otherwise). Breaking out of the loop stops fetching.

```ts
for await (const tag of client.iterateTags()) console.log(tag.name);
```

## Snapshots

### `createSnapshot(url: string, options?): Promise<SnapshotCreated>`

Queue a URL. Returns at once with `status: "pending"`. `options` is `{ colorScheme?, signal? }`; `colorScheme` (`"light"` or `"dark"`) is the theme the page is archived in, and defaults to the server's `WEBFROST_COLOR_SCHEME`.

```ts
const snapshot = await client.createSnapshot("https://example.com");
// { id: 1, url: "https://example.com", status: "pending" }

await client.createSnapshot("https://example.com", { colorScheme: "dark" });
```

The server archives in the background. Poll `getSnapshot` until `status` is no longer `pending`; it becomes `done` (at least one extractor produced output) or `failed`.

### `listSnapshots(options?): Promise<SnapshotPage>`

`options` is `{ page?, limit?, status? }`. Results are newest first. The second argument is `{ signal }`.

```ts
const { items, total, page, limit } = await client.listSnapshots({ page: 1, limit: 20 });
const pending = await client.listSnapshots({ status: "pending" });
```

### `iterateSnapshots(options?): AsyncGenerator<Snapshot>`

Every snapshot matching the filters, one page at a time (100 per request unless `limit` says otherwise). `options` is `{ page?, limit?, status?, signal? }`. It is lazy: breaking out of the loop stops fetching.

```ts
for await (const snapshot of client.iterateSnapshots({ status: "done" })) {
  console.log(snapshot.id, snapshot.url);
}
```

### `searchSnapshots(query): Promise<SearchResult[]>`

Full-text search; returns the first page of results.

```ts
const results = await client.searchSnapshots("climate change");
// [{ id, url, snippet: "...climate <mark>change</mark>...", rank, status, createdAt, title, extractors, tags }]
```

Snippets are HTML-escaped by the server; the only markup is a literal `<mark>` and `</mark>`. Render them as text, never as raw HTML.

### `searchSnapshotsPage(query, options?): Promise<SearchPage>`

Paginated search. `options` is `{ page?, limit? }`.

```ts
const { items, total } = await client.searchSnapshotsPage("climate change", { page: 2, limit: 20 });
```

### `getSnapshot(id: number): Promise<SnapshotDetail | null>`

Resolves to `null` when the snapshot does not exist. Otherwise the list fields plus `archiveResults` and `extractorMeta`. Each archive result has `downloadUrl` and `previewUrl` (`null` unless the extractor has a preview), which the SDK resolves to absolute URLs against `baseUrl`, as it does `screenshotUrl`. `content` holds the data only for inline results (`readability`, `html`) and is `null` for file-backed ones; storage paths never reach the client.

```ts
const detail = await client.getSnapshot(1);
detail?.extractorMeta["pdf"]; // { status: "success", durationMs, fileSizeBytes }
for (const result of detail?.archiveResults ?? []) {
  console.log(result.extractor, result.downloadUrl, result.previewUrl);
}
```

### `deleteSnapshot(id: number): Promise<boolean>`

`true` when deleted, `false` when it did not exist.

### `archiveUrl(id, extractor, kind?): string`

A URL for `<a href>`, `<img src>` or `<iframe src>`. `kind` is `"download"` (default) for the stored file, or `"preview"` for the sandboxed HTML preview that some extractors have. The URL carries no credentials: the browser sends the session cookie. An API key cannot go in a URL, so use `downloadArchive` with one.

```ts
client.archiveUrl(1, "screenshot"); // http://localhost:3000/api/v1/snapshots/1/archives/screenshot/download
client.archiveUrl(1, "singlefile", "preview");
```

### `downloadArchive(id, extractor, options?): Promise<Response>`

Fetches an archived result with the client's auth, timeout and signal, and returns the `Response`: read it with `.blob()`, `.arrayBuffer()` or `.body`. `options` is `{ kind?, signal? }`. The timeout ends when the headers arrive, so a large body is not cut off. Throws `NOT_FOUND` when there is no such result, and `BAD_REQUEST` for an extractor name the server does not know.

```ts
const res = await client.downloadArchive(1, "warc");
const blob = await res.blob();
```

## Tags

| Method | Returns | Notes |
|---|---|---|
| `listTags(options?, request?)` | `Page<Tag>` | Ordered by name |
| `createTag(name, color?)` | `Tag` | `color` is any string up to 32 characters, such as `"#4f46e5"`; it is `null` on the tag when omitted. Throws `CONFLICT` (`409`) on a duplicate name. |
| `deleteTag(id)` | `boolean` | `false` when it did not exist |
| `listSnapshotTags(snapshotId, options?, request?)` | `Page<Tag>` | An empty page when the snapshot does not exist |
| `addTagToSnapshot(snapshotId, tagId)` | `Tag` | Throws `NOT_FOUND` for an unknown snapshot or tag; adding a tag that is already there succeeds |
| `removeTagFromSnapshot(snapshotId, tagId)` | `boolean` | `false` when it did not exist |

```ts
const tag = await client.createTag("research", "#4f46e5");
await client.addTagToSnapshot(1, tag.id);
```

## Schedules

| Method | Returns | Notes |
|---|---|---|
| `listSchedules(options?, request?)` | `Page<Schedule>` | Oldest first |
| `createSchedule(url, cron)` | `Schedule` | URL schedules only. Throws `VALIDATION` for a bad URL or cron expression |
| `updateSchedule(id, { paused })` | `Schedule` | Pause or resume. Throws `NOT_FOUND` for an unknown id |
| `deleteSchedule(id)` | `boolean` | `false` when it did not exist |

```ts
const schedule = await client.createSchedule("https://example.com", "0 9 * * *");
await client.updateSchedule(schedule.id, { paused: true });
```

## Import

### `importUrls(options): Promise<ImportResult>`

```ts
const result = await client.importUrls({
  url: "https://example.com/feed.xml",
  format: "rss", // "rss" | "opml" | "netscape" | "text"
});
// { queued: 12, skipped: 3, total: 15, format: "rss" }
```

`options` is `{ url?, content?, format? }`: pass a `url` to fetch or raw `content` to parse. `format` is detected when omitted. `listImports(options?, request?)` returns the history as a `Page<ImportRecord>`, newest first. Throws `PAYLOAD_TOO_LARGE` for an import over the server's size or URL-count limits, and `FETCH_FAILED` when the `url` cannot be fetched.

### `importFile(file, format?, options?): Promise<ImportResult>`

Uploads a file (OPML, Netscape bookmarks, RSS or plain text) as multipart form data. The format is detected from the file name and content unless `format` is given. A bare `Blob` has no name, so pass `options.filename` (such as `"bookmarks.html"`) to help detection. `options` is `{ filename?, signal? }`.

```ts
await client.importFile(new Blob([text]), "text", { filename: "urls.txt" });
await client.importFile(fileInput.files[0]); // a File keeps its own name
```

## Auth, setup and administration

| Method | Returns |
|---|---|
| `getSetupStatus()` | `{ needsSetup, publicRead, setupTokenRequired }` |
| `completeSetup(username, password, setupToken?)` | `{ apiKey }`. The password needs at least 8 characters. Pass `setupToken` when the server sets `WEBFROST_SETUP_TOKEN` (`setupTokenRequired`). |
| `login(username, password)` | `{ ok }`. Sets a session cookie, so it is for browsers; elsewhere use an API key. |
| `logout()` | `void`. Not being logged in is not an error. |
| `getMe()` | `{ username }`, with `null` for API-key auth |
| `changePassword(currentPassword, newPassword)` | `void`. Throws `WebFrostError` with status `403` and code `INVALID_CREDENTIALS` when the current password is wrong, `400` `VALIDATION` for a new password under 8 characters. |
| `getStats()` | `DashboardStats` |
| `getServerInfo()` | `{ version, storagePath, snapshotCount }` (`GET /settings/info`) |
| `listApiKeys(options?, request?)` | `Page<ApiKey>`, active keys only, oldest first |
| `createApiKey(name, { expiresAt?, signal? })` | `ApiKeyCreated`, which includes `rawKey`, shown once. `expiresAt` is an ISO 8601 string or a `Date` in the future; omit it for a key that never expires. |
| `revokeApiKey(id: string)` | `boolean`. `false` when the key did not exist. |

## Types

Every type is exported from the package root, for example `import type { Snapshot, SnapshotStatus, SetupResult, ExtractorMeta, RequestOptions } from "@webfrost/sdk"`, as are the error code unions `ApiErrorCode`, `ClientErrorCode` and `WebFrostErrorCode`.

```ts
type SnapshotStatus = "pending" | "done" | "failed";
type ImportFormat = "rss" | "opml" | "netscape" | "text";
type ScheduleRunStatus = "success" | "failed";

interface SnapshotCreated { id: number; url: string; status: "pending" }

interface Snapshot {
  id: number;
  url: string;
  status: SnapshotStatus;
  createdAt: string;
  extractors: string[]; // extractors that succeeded
  tags: Tag[];
  title: string | null;
  excerpt: string | null;
  screenshotUrl: string | null; // absolute URL, or null
}

interface ArchiveResult {
  id: number;
  extractor: string;
  content: string | null; // data for inline results only; null for file-backed ones
  downloadUrl: string; // absolute, resolved against baseUrl
  previewUrl: string | null; // set for dom-snapshot and singlefile
  createdAt: string;
}

interface SnapshotDetail extends Snapshot {
  archiveResults: ArchiveResult[];
  extractorMeta: Record<
    string,
    { status: "success" | "failed"; durationMs: number | null; fileSizeBytes: number | null; error?: string }
  >;
}

interface Page<T> { items: T[]; total: number; page: number; limit: number }
type SnapshotPage = Page<Snapshot>

interface Tag { id: number; name: string; slug: string; color: string | null; createdAt: string }

interface SearchResult {
  id: number; url: string; snippet: string; rank: number;
  status: SnapshotStatus | null; // null when the server did not report one
  createdAt: string; title: string | null; extractors: string[]; tags: Tag[];
}
type SearchPage = Page<SearchResult>

interface Schedule {
  id: number; url: string; cron: string; createdAt: string;
  lastRunAt: string | null; nextRunAt: string | null;
  paused: boolean; lastStatus: ScheduleRunStatus | null; consecutiveFailures: number;
}

interface ImportResult { queued: number; skipped: number; total: number; format: ImportFormat }
```

`DashboardStats`, `ServerInfo`, `ApiKey`, `ApiKeyCreated` and `ImportRecord` match the response shapes in the [REST API reference](/docs/reference/rest-api#stats-and-settings); timestamps are ISO 8601 strings.
