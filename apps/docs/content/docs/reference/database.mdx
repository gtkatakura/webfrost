WebFrost keeps all metadata in one SQLite file, `archive.db`, in `WEBFROST_DIR`. `@webfrost/core` (`packages/core/src/db.ts`) creates and migrates the schema when a connection opens. The schema version is tracked in `PRAGMA user_version` (currently 2), so migration runs once per archive rather than on every connection.

Every connection sets `journal_mode = WAL`, `foreign_keys = ON` and `busy_timeout = 5000`, so a competing writer is waited for up to 5 seconds instead of failing with `SQLITE_BUSY`. The server, each background pipeline and the CLI open their own connection.

Column names are `snake_case`. Timestamps are SQLite `datetime('now')` strings in UTC.

## Tables

### snapshots

One row per archived URL.

| Column | Type | Description |
|---|---|---|
| `id` | INTEGER | Primary key (autoincrement). Also names the snapshot's directory. |
| `url` | TEXT | The archived URL |
| `status` | TEXT | `pending`, `done` or `failed`. `done` means at least one extractor produced output. |
| `created_at` | TEXT | Creation time |

### archive_results

One row per extractor per run. A failed extractor has `error` set and no `content`.

| Column | Type | Description |
|---|---|---|
| `id` | INTEGER | Primary key |
| `snapshot_id` | INTEGER | References `snapshots.id` |
| `extractor` | TEXT | `warc`, `readability`, `html`, `pdf`, `screenshot`, `dom-snapshot`, `singlefile`, `media` or `media-metadata` |
| `content` | TEXT | Inline content (`html`, `readability`) or a storage reference to the file |
| `duration_ms` | INTEGER | How long the extractor ran. Nullable. |
| `error` | TEXT | Failure reason, or null on success |
| `created_at` | TEXT | Creation time |

A storage reference is an absolute file path with the filesystem backend and `s3:<key>` with S3.

### job_queue

Background job state, one row per snapshot.

| Column | Type | Description |
|---|---|---|
| `id` | INTEGER | Primary key |
| `snapshot_id` | INTEGER | References `snapshots.id` |
| `status` | TEXT | `pending`, then `running`, then `done` or `failed` |
| `heartbeat_at` | TEXT | Lease. A live pipeline refreshes it every 10 seconds. Nullable. |
| `attempts` | INTEGER | How many times the job was re-queued after being orphaned. Default 0. |
| `created_at` | TEXT | Creation time |

A `pending` snapshot whose `heartbeat_at` is older than 45 seconds is adopted by a recovery sweep. After 3 attempts it is marked `failed`. See [Pipeline](/docs/architecture/pipeline#jobs-leases-and-recovery).

### tags and snapshot_tags

`tags`:

| Column | Type | Description |
|---|---|---|
| `id` | INTEGER | Primary key |
| `name` | TEXT | Unique |
| `slug` | TEXT | URL-safe name, unique |
| `color` | TEXT | Hex color such as `#4f46e5`. Nullable. |
| `created_at` | TEXT | Creation time |

`snapshot_tags` is the many-to-many join: `snapshot_id` and `tag_id` (composite primary key). Rows are deleted with their snapshot or tag.

### schedules

| Column | Type | Description |
|---|---|---|
| `id` | INTEGER | Primary key |
| `url` | TEXT | URL or RSS feed URL |
| `cron` | TEXT | Five-field cron expression, evaluated in the process time zone |
| `kind` | TEXT | `url` or `rss_feed` |
| `paused` | INTEGER | `0` active, `1` paused |
| `last_run_at` | TEXT | Last claim time. Nullable. |
| `next_run_at` | TEXT | When it is next due. A process claims a due schedule by advancing this value atomically. |
| `last_status` | TEXT | `success`, `failed` or null |
| `consecutive_failures` | INTEGER | Resets on success |
| `created_at` | TEXT | Creation time |

### admin_users

| Column | Type | Description |
|---|---|---|
| `id` | INTEGER | Primary key |
| `username` | TEXT | Unique |
| `password_hash` | TEXT | bcrypt hash |
| `created_at` | TEXT | Creation time |

### sessions

Server-side login sessions. A cookie is valid only while its row exists, so logout and password changes revoke it immediately.

| Column | Type | Description |
|---|---|---|
| `id` | TEXT | Primary key |
| `username` | TEXT | The admin user |
| `created_at` | TEXT | Creation time |
| `expires_at` | TEXT | Expiry (7 days after login) |

### api_keys

| Column | Type | Description |
|---|---|---|
| `id` | TEXT | Primary key (UUID) |
| `name` | TEXT | Label |
| `key_hash` | TEXT | SHA-256 of the key. The key itself is never stored. |
| `expires_at` | TEXT | Optional expiry |
| `last_used_at` | TEXT | Last successful use. Nullable. |
| `revoked_at` | TEXT | Set when revoked |
| `created_at` | TEXT | Creation time |

### imports

History of bulk imports, one row per operation.

| Column | Type | Description |
|---|---|---|
| `id` | TEXT | Primary key (UUID) |
| `source_url` | TEXT | Feed or file URL. Null for uploads and inline content. |
| `format` | TEXT | `rss`, `opml`, `netscape` or `text` |
| `queued` | INTEGER | URLs queued |
| `skipped` | INTEGER | URLs skipped (already archived, or could not be queued) |
| `created_at` | TEXT | Creation time |

### snapshots_fts

A SQLite FTS5 virtual table for full-text search. Its `rowid` is the snapshot id.

```sql
CREATE VIRTUAL TABLE snapshots_fts USING fts5(url, title, text_content, tags);
```

A snapshot is indexed when it finishes `done`, from its Readability output. Tag names are part of the index and stay in sync when tags change after archiving. Rebuild everything with `webfrost search:rebuild`.

## Indexes

| Index | On |
|---|---|
| `idx_archive_results_snapshot` | `archive_results (snapshot_id, extractor)` |
| `idx_job_queue_snapshot` | `job_queue (snapshot_id)` |
| `idx_snapshots_url` | `snapshots (url)` |
| `idx_snapshots_status` | `snapshots (status)` |
| `idx_snapshots_created_at` | `snapshots (created_at)` |
| `idx_snapshot_tags_tag` | `snapshot_tags (tag_id)` |
| `idx_schedules_next_run` | `schedules (next_run_at)` |
| `idx_api_keys_hash` | `api_keys (key_hash)` |

## Direct access

You can read `archive.db` with any SQLite client. Prefer read-only queries while the server runs.

```bash
sqlite3 data/archive.db ".tables"
sqlite3 data/archive.db \
  "SELECT id, status, url, created_at FROM snapshots ORDER BY id DESC LIMIT 10;"
sqlite3 data/archive.db \
  "SELECT extractor, error FROM archive_results WHERE snapshot_id = 1;"
```
